# GitHub discoverability checklist

Changing repository files does **not** update GitHub's About text or Topics. The repository owner must edit these in GitHub settings (or through the authenticated GitHub CLI).

## Suggested About description

Reverse-engineered USB-C replacement adapter for Potensic ATOM DSRC02A controllers, with KiCad schematic, measured wiring, prototype test and 3D-printable holder.

## Suggested Topics

`potensic`, `potensic-atom`, `usb-c`, `replacement-cable`, `reverse-engineering`, `kicad`, `hardware`, `3d-printing`, `drone`, `android-aoa`

## Recommended next steps

1. Add real photographs of the original cable, the completed adapter, connector labels and the printed holder. Remove personal and device identifiers before publishing; do not use an illustrative image as proof of a test.
2. If publishing `v0.1.0`, ensure the release notes match the tested revision and clearly state the compatibility limitations and experimental status.
3. Document Android handset version, controller firmware, exact wiring revision and test conditions for future reproduction.
4. Keep a prominent reciprocal link to [PotensicProxy_TAF](https://github.com/TheAndiF/PotensicProxy_TAF).
5. Resolve the attribution/publication items in [release checklist](release-checklist.md) before presenting this as a finished public release.

Search ranking and traffic cannot be guaranteed. Precise documentation and authentic evidence are more useful than adding unrelated keywords.
